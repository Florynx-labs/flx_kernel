# FLX Kernel benchmark protocol

This document defines how to collect a baseline for issue #31. It deliberately contains no
invented performance numbers. A baseline is valid only when generated by a checked-in harness
against the kernel revision being measured.

## Required environment record

Every run must record:

- Git commit SHA and whether the worktree was clean;
- Rust toolchain version, target triple, and release profile;
- QEMU version, machine/CPU model, accelerator (TCG/KVM), memory size, and firmware;
- host OS/kernel and CPU model for host-side harnesses;
- number of warm-up and measured iterations;
- raw samples, median, p95, p99, minimum, and maximum;
- whether the result is a host microbenchmark or a guest/kernel measurement.

Never compare host-side timings with guest/kernel timings as if they measured the same path.

## Required kernel measurements

| Area | Operation | Required correctness check |
|---|---|---|
| Physical memory | frame allocate/free throughput and latency | allocated frames are unique, aligned, and returned exactly once |
| Heap | allocation/free size classes and growth | allocator self-tests and guard/canary checks |
| Address spaces | activate address space | active root readback and mapping isolation |
| TLB | single-page and full invalidation | stale translation is not observable after mutation |
| Synchronization | uncontended and contended lock acquisition | mutual exclusion and interrupt-context contract |
| Interrupts | interrupt-to-handler latency | expected interrupt count and no unexpected vectors |

## Measurement rules

1. Build the same release artifact for baseline and candidate revisions.
2. Run at least 30 measured batches after warm-up; preserve each raw sample.
3. Report distributions, not only a single average.
4. Repeat each QEMU configuration at least three times.
5. Do not disable memory safety, validation, or synchronization to improve a score.
6. Every optimization must include before/after data and the correctness test for the affected path.
7. If the operation does not exist yet (for example, production context switching), mark it
   **not measurable** rather than substituting an unrelated host benchmark.

## Result format

Store results as CSV under benchmarks/results/<target>/<commit>.csv and a Markdown summary
beside it. CSV columns:

benchmark,target,commit,environment,iteration,elapsed_ns,unit,notes

The Markdown summary must include the environment record, command line, raw artifact link,
median/p95/p99, and any deviations from this protocol.
